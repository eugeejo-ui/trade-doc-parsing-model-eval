# 1.5단계 — 정답지 생성

**상태**: 진행
**선행**: 1단계 완료 (`outputs/kaggle_ground_truth.csv` 1,414행)
**소요 예상**: 30분

---

## 1. 목적

모델 실행 **전에** 조건별 정답지를 만들어 파일로 확정한다.

```
1. 정답지 생성        ← 이 단계
2. 정답지 파일 저장   ← 확정. 이후 수정 금지
3. 모델 실행
4. 채점
```

순서가 뒤집히면 "결과를 보고 정답을 고쳤다"는 의심을 받는다.

---

## 2. 확정 사항

| 항목 | 결정 |
|---|---|
| 하자율 | **0.7** (ICC 1차 제시 거절률) |
| 하자 대상 건 | **모든 조건에서 동일** |
| 난수 시드 | **42** 고정 |
| 금액 주입 방향 | **증가·감소 반반** |
| 통화 자릿수 | **소수 둘째 자리** |
| 기한 마감 간격 | **발행일 + 21일** (UCP 600 제14조(c)) |

### 2.1 하자 대상을 조건마다 바꾸지 않는 이유

같은 건에 하자를 심어야 조건 간 비교가 깨끗해진다.
조건마다 대상이 다르면 탐지율 차이가 "조건 때문"인지
"표본이 달라서"인지 구분되지 않는다.

### 2.2 금액 방향을 반반으로 하는 이유

한쪽으로만 틀리면 모델이 방향을 학습할 여지가 생긴다.
증가·감소를 절반씩 섞는다.

## 4. 규칙별 주입 방식

### 4.1 금액

```
정상: 조건금액 = round(송장금액, 2)
하자: 조건금액 = round(송장금액 × (1 ± r), 2)
                                  ↑ 반반
```

**반올림 후 차이가 eps(0.01) 이하면 정답지를 "정상"으로 수정한다.**
0.1% 조건에서 28건(1.98%, 금액 1.71~14.82원) 발생이 실측됐다.

고치는 것은 **정답지**이며 모델 출력이 아니다.
하자를 심으려다 실패해 두 값이 실제로 같아진 건이므로,
정답지를 사실에 맞추는 것이다.

### 4.2 기한

```
정상: 마감일 = 발행일 + 21일        → 발행일이 빠름 → 통과
하자: 마감일 = 발행일 - k일         → 발행일이 늦음 → 하자
              k ∈ {1, 3, 7, 30}
```

일 단위이므로 반올림 소멸 문제가 없다.

### 4.3 명칭 — 3단계

금액·기한과 달리 정도를 수치로 나눌 수 없어 유형으로 나눈다.

| 단계 | 방식 | 예 |
|---|---|---|
| 약 | 법인격 표기 치환 | `ABC Ltd.` → `ABC Limited` |
| 중 | 한 글자 치환 | `ABC Trading` → `ABG Trading` |
| 강 | 완전히 다른 상호 | `ABC Trading` → `XYZ Corp` |

**UCP 600 엄격일치에서는 세 단계 모두 하자다.**
다만 모델이 읽어내는 난이도가 다르므로 나누어 측정한다.

하자 건을 3등분해 각 단계에 배정한다.
`rules.py`의 `name_matches(strict=True)`를 사용한다.

## 5. 출력 형식

각 정답지 파일의 컬럼:

| 컬럼 | 내용 |
|---|---|
| `file_name` | 이미지 파일명 (채점 시 매칭 키) |
| `field` | `total` / `invoice_date` / `seller_name` |
| `doc_value` | 송장에 적힌 값 = 모델이 읽어야 할 값 |
| `cond_value` | 합성한 조건값 |
| `is_defect` | 하자 여부 (최종 확정값) |
| `injected` | 주입을 시도했는지 (소멸 건 추적용) |
| `amount` | 금액 (사후 층화 분석용) |

`injected=True` 이면서 `is_defect=False` 인 건이 **반올림 소멸 건**이다.
