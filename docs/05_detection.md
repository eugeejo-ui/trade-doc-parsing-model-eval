# 5단계 — 규칙 적용 및 탐지율 환산

**상태**: 완료
**선행**: 4단계 완료 (`extracted.csv` 300행), 1.5단계 정답지 9개
**실행 위치**: 로컬
**실행일**: 2026-09-23

---

## 1. 목적

모델이 읽은 값에 **규칙 3종을 적용**해 하자 여부를 판정하고,
1.5단계에서 확정한 정답지와 대조한다.

**산출: 탐지율 `r`, 오탐률 `p`** — 브리핑 6절 비용 수식의 실험 변수.

```
절감 = N×d×r×R − N×d×r×t_f − N×(1-d)×p×t_v − C
              ↑                        ↑
            탐지율                   오탐률
```

---

## 2. 구조

```
모델이 읽은 값        합성 조건값
(extracted.csv)      (truth_*.csv)

                  │
            하자 판정
                  │
```

검증한 함수를 그대로 적용한다는 것이 이 프로젝트의 설계 전제였다.

## 4. 판정 로직

### 4.1 금액

```python
predicted = not amount_matches(모델이_읽은_값, 조건값, eps=0.01)
```

### 4.2 기한

```python
predicted = not date_before(모델이_읽은_날짜, 마감일)
```

`date_before`는 **0단계에서 검증되지 않은 함수다.**
BPI 2019에 납기·마감 필드가 없어 검증할 수 없었다.

### 4.3 명칭

```python
predicted = not name_matches(모델이_읽은_상호, 조건상호, strict=True)
```

`name_matches`도 **미검증 함수다.**
BPI의 Vendor/Name이 케이스 단위 단일값이라 대조 짝이 없었다.

### 4.4 추출 실패 처리

값을 못 읽으면 대조가 불가능하다. **보수적으로 하자 판정**한다.
실제로는 추출 실패가 0건이었으므로 이 경로는 사용되지 않았다.

## 5. 지표 정의

```
                 정답: 하자      정답: 정상
판정: 하자         TP              FP
판정: 정상         FN              TN

r (탐지율) = TP / (TP + FN)      하자를 하자로 잡은 비율
p (오탐률) = FP / (FP + TN)      정상을 하자로 잘못 잡은 비율
```

## 7. 주입 폭 민감도 ★

```
금액  0.1% / 1% / 10% / 50%   →  100.0 / 100.0 / 99.1 / 100.0
기한  1일 / 3일 / 7일 / 30일   →  100.0 / 100.0 / 100.0 / 100.0
```

**하자 크기를 500배 키워도 탐지율이 같다.**

이는 0단계에서 ε를 0.001~10 EUR로 바꿔도 불일치 164건이
고정됐던 것과 **같은 구조**다.

### 결론

> 탐지율은 하자 크기가 아니라 **파싱 정확도**가 결정한다

모델이 제대로 읽으면 어느 주입 수준에서든 판정이 정확하다.

| 주입 | 조건값 | 모델값 | 차이 | ε(0.01) 대비 |
|---|---|---|---|---|
| 50% | 190.97 | 127.31 | 63.66 | 충분히 큼 |
| 0.1% | 127.44 | 127.31 | 0.13 | **충분히 큼** |

0.1%에서도 차이 0.13이 ε(0.01)보다 13배 크다. 정확히 잡힌다.

## 8. `amount_10`만 99.1%인 이유 — 우연의 일치

10%가 0.1%보다 낮게 나왔다. 상식과 반대다.

원인은 **주입률과 부가세율이 겹친 것**으로 보인다.

```
세전/세후 오답 건
  정답 812.56 (Net)  →  모델 893.82 (Gross)
  812.56 × 1.1 = 893.82        ← 부가세 10%

10% 주입
  조건값 = 812.56 × 1.1 = 893.82
  모델값 =                893.82
                          ↑ 일치 → "하자 없음" 판정 → 놓침
```

잘못 읽은 값이 주입값과 정확히 같아져 하자를 놓쳤다.

**두 모델이 동일하게 겪으므로 비교에는 영향이 없다.**

## 9. 오탐 2.3~2.5%의 정체

금액 조건에서만 오탐이 나온다. 기한·명칭은 0%다.

4단계에서 확인한 **세전/세후 표기 불일치 3건** 중
정상으로 배정된 건이 오탐으로 잡힌 것이다.

```
모델 893.82 (Gross)  vs  조건 812.56 (Net 기준 합성)
→ 정상 건인데 불일치 → 오탐
```

**정답지 쪽 표기 문제이며 모델 오류가 아니다.**
두 모델이 동일하게 겪는다.

## 10. 왜 두 모델이 완전히 같은가

추출값 450개(3필드 × 150건)를 직접 대조했다.

| 필드 | 불일치 |
|---|---|
| 금액 | **0건** |
| 날짜 | **0건** |
| 상호 | **1건** |

유일한 차이도 대소문자다.

```
granite  Robinson, McClain and Moore
paddle   Robinson, Mcclain and Moore
                    ↑ C 하나
```

`name_matches`가 소문자로 정규화하므로 둘 다 정답 처리됐다.

**449/450이 완전히 동일하다.**
답안이 같으면 채점 기준을 어떻게 바꿔도 점수가 같다.
ε·주입 폭을 흔들어도 차이가 나오지 않은 이유가 이것이다.

## 12. 주의 — 하지 않은 것

브리핑 6절의 경고를 유지한다.

- **측정된 r을 d로 바꿔 쓰지 않는다.** `d=0.7`은 ICC의 1차 제시 거절률이다
- 회사 규모로 나누지 않는다. `N`은 입력값으로 받는다
- 0단계의 1.91%는 기업 내부 구매 프로세스 수치이므로 쓰지 않는다
