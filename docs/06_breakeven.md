# 6단계 — 손익분기 계산

**상태**: 1차 실행 완료 / 전제 재검토 필요
**선행**: 5단계 완료 (r = 100%, p = 2.5%)
**실행 위치**: 로컬
**실행일**: 2026-09-24

---

## 1. 목적

**AI 도입이 언제부터 이득인가**를 구한다.

두 모델 중 무엇을 고를지가 아니다. 둘 다 Apache 2.0 무료이므로 비교할 가격이 없다.

브리핑 9절의 결론 문장 중 하나를 완성한다.

> "월 N건 이상이면 Granite 탐지율로도 손익분기를 넘는다.
>  그 이하면 오탐 확인 부담이 절감을 먹는다."

**N을 숫자로 채우는 것**이 이 단계다.

> 이 문장의 후반부는 실측 결과 사실이 아니었다. 9절 참조.

---

## 2. 구조

```
AI 없음   서류 제출 → 은행 반려 → 수정 → 재제출 → 재심사 대기
                                                    ↑ 최대 5영업일 (UCP 600)

AI 있음   서류 제출 전 AI가 하자를 걸러냄
          + 오탐 확인 부담
          + 월 고정 운영비
```

```
절감 = N에 비례해 증가
C   = 고정
      ↓
어느 N에서 역전 → 손익분기
```

**`C`가 고정비여야 손익분기가 생긴다.**
건당 비용으로 잡으면 `N`에 함께 비례해 교차점이 사라진다.

---

## 3. 비용 수식 (브리핑 6절)

```
AS-IS = N × (t_w + t_c) + N × d × R

TO-BE = N × (t_w + t_c')
      + N × d × r × t_f          AI가 잡은 하자 → 수정
      + N × (1-d) × p × t_v      오탐 확인
      + N × d × (1-r) × R        놓친 하자 → 재제출
      + C

절감 = N×d×r×R − N×d×r×t_f − N×(1-d)×p×t_v − C
```

### 손익분기

```
N* = C / [ d×r×R − d×r×t_f − (1-d)×p×t_v ]
```

분모가 **건당 순절감액**이다. 0 이하이면 손익분기가 존재하지 않는다.

---

## 4. 변수 처리

| 기호 | 의미 | 값 | 출처 |
|---|---|---|---|
| **r** | 탐지율 | **1.00** | **5단계 실험** |
| **p** | 오탐률 | **0.025** | **5단계 실험** |
| d | 하자 발생률 | 0.70 | ICC 1차 제시 거절률 |
| N | 월 서류 건수 | **입력** | 기업별 상이 |
| R | 재제출 1회 **총비용** | **입력** | 기업별 상이 |
| t_f | 하자 수정 시간 | **입력** | 기업별 상이 |
| t_v | 오탐 확인 시간 | **입력** | 기업별 상이 |
| C | 월 고정 운영비 | **입력** | 기업별 상이 |

### 4.1 R에 포함되는 것 ★

`R`은 시간이 아니라 **비용**이다.

```
① 서류 재작성 인건비                    작음
② 은행 재심사 대기 5영업일의 기회비용   ← 지배적
     · 대금 회수 지연에 따른 자금조달 비용
     · 선적·납기 지연 위약금
     · 신용장 유효기일 초과 위험
     · 거래처 신뢰도 손상
```

브리핑 6절이 "R이 t_f·t_v와 자릿수가 다르다"고 한 이유가 이것이다.
`t_f`·`t_v`는 분 단위 인건비지만 `R`은 영업일 단위 기회비용을 포함한다.

**기업별 편차가 크다.** 자금 여유가 있는 대기업은 5일 지연이 크지 않으나,
어음으로 자금을 돌리는 중소기업에는 치명적이다.
브리핑 3절이 지적한 "자산 적은 제조 혁신기업의 자금조달 격차"가 여기에 해당한다.

### 4.2 왜 대부분 입력값인가

브리핑 6절이 명시한다.

> 회사 규모 데이터는 구할 수 없음(개별 기업 신용장 건수 비공개).
> 규모로 나누지 말고 **입력값으로 받을 것**

`C`도 같다. 은행 내부 서버 구축비·전력·인력 단가는 공개 자료가 없다.
추정치를 지어내면 브리핑 10절 위반이다(직접 검증하지 않은 내용 금지).

### 4.3 GPU 시간 기반 C를 쓰지 않는 이유 (철회 기록)

초기에 `C = GPU 시간당 단가 × 장당 소요 × N` 을 검토했으나 **철회**했다.

**① 단가 출처가 없다**

브리핑 4절은 **은행 내부 서버 직접 구축**을 전제한다.
클라우드 GPU 요금을 가져오면 전제와 모순된다.

**② 자릿수가 맞지 않는다**

```
AI 처리     26.3초 / 장
사람 왕복   최대 5영업일
```

절감액이 일 단위인데 비용에 초 단위를 붙이면 균형이 깨진다.

**③ 실측 환경이 다르다**

Tesla T4(2018년 추론용 저가 GPU)에서 측정했다.
은행 내부 구축 시 표준인 A100/H100에서의 소요는 모른다.

**④ 건당 비용이면 손익분기가 사라진다**

N에 비례하는 항을 C로 두면 교차점이 생기지 않는다.

### 4.4 d = 0.7의 의미

**신용장 서류를 은행에 내면 10건 중 7건이 1차 제시에서 거절된다.**

- 출처: ICC 은행위원회 선임기술자문 Dave Meynell, 1차 제시 거절률 65~80%
- 원인: UCP 600 엄격일치. 단수/복수 차이, 단가 1센트 차이로도 거절

**반드시 구분할 것 (브리핑 11절)**

| | |
|---|---|
| 1차 제시 거절률 | 70% ← 이 값 |
| 최종 지급거절률 | 훨씬 낮음. 대부분 수정 후 통과 |

**이미 사람이 점검한 뒤의 값**이므로, 수식에서 사람 점검 항을 따로 빼면 이중 차감이다.

## 5. 정규화 — 모든 금액을 R 단위로

절대 금액을 모르므로 **R(재제출 1회 비용)을 1.0으로 두고** 나머지를 비율로 표현한다.

```
C = 10      "월 고정비가 재제출 10건 값에 해당"
t_f = 0.05  "수정 시간이 재제출의 5% 수준"
```

**모르는 값이 둘(R, C)에서 하나(C/R 비율)로 줄어든다.**

## 6. 결과 (2026-09-24)

### 6.1 건당 순절감 (R = 1.0)

| t_f/R | t_v/R | 건당 순절감 |
|---|---|---|
| 0.00 | 0.00 | 0.7000 |
| 0.02 | 0.02 | 0.6858 |
| 0.05 | 0.05 | 0.6646 |
| 0.10 | 0.10 | 0.6292 |
| 0.20 | 0.20 | 0.5585 |

수정·확인 비용을 R의 20%로 크게 잡아도 순절감이 0.56 남는다.

### 6.2 손익분기 N

| C (R 단위) | t_f=t_v=0% | 2% | 5% | 10% | 20% |
|---|---|---|---|---|---|
| 1 | 1건 | 1건 | 2건 | 2건 | 2건 |
| 5 | 7건 | 7건 | 8건 | 8건 | 9건 |
| 10 | 14건 | 15건 | 15건 | 16건 | 18건 |
| 50 | 71건 | 73건 | 75건 | 79건 | 90건 |
| 100 | 143건 | 146건 | 150건 | 159건 | 179건 |
| 500 | 714건 | 729건 | 752건 | 795건 | 895건 |

**관계: N* ≈ C / 0.66 ≈ C × 1.5** (거의 비례)

> 읽는 법: 월 고정비가 재제출 10건 값이고 수정·확인 비용이
> 재제출의 5% 수준이면, 월 15건 이상부터 이득

### 6.3 R 민감도 — C 고정, R만 변동

| R (기준 대비) | 손익분기 N | 해석 |
|---|---|---|
| 0.25배 | 60건 | 자금 여유 큰 대기업 |
| 0.50배 | 30건 | |
| 1.00배 | 15건 | 기준 |
| 2.00배 | 8건 | |
| 4.00배 | 4건 | 자금 회전 빡빡한 중소기업 |
| 8.00배 | 2건 | 납기 위약금 있는 계약 |

**재제출 비용이 클수록 손익분기가 낮아진다.** R이 4배면 필요 건수는 1/4.

> 초기 코드는 C도 R에 비례시켜 손익분기가 불변으로 나왔다.
> 분자·분모를 같은 비율로 곱한 동어반복이었으므로 수정했다.

## 7. 브리핑 9절 결론 문장의 오류 ★

브리핑의 결론 문장은 이랬다.

> "월 N건 이상이면 손익분기를 넘는다.
>  **그 이하면 오탐 확인 부담이 절감을 먹는다.**"

**측정 결과 오탐은 절감을 먹지 않는다.**

### 7.1 항의 크기

```
절감 항        d × r × R     = 0.700
수정 비용 항   d × r × t_f   = 0.035
오탐 확인 항   (1-d) × p × t_v = 0.000375   ← p=2.5%
```

**오탐 항이 수정 비용 항의 1/93, 절감 항의 1/1,867이다.**
`p`를 50%로 올려도 0.0075에 그친다.

### 7.2 근거는 브리핑 자신이다

브리핑 6절이 이렇게 적었다.

> R이 지배 변수. 재작성 + 은행 재심사 대기(UCP 600상 최대 5영업일)라
> **t_f·t_v와 자릿수가 다름**

`t_v << R` 이 브리핑의 전제다. 그러면 오탐 항은 구조적으로 작아진다.
**브리핑 6절과 9절이 서로 모순된다.** 6절이 맞으면 9절 후반부는 성립하지 않는다.

### 7.3 실제로 절감을 먹는 것

```
절감 = N × 0.6646 − C
                    ↑ 고정 운영비
```

`N`이 작을 때 음수가 되는 이유는 **고정 운영비**다. 오탐이 아니다.

건당 순절감이 음수가 되려면 다음이 성립해야 한다.

```
0.7 × R < 0.7 × t_f + 0.3 × p × t_v
```

`p`가 100%여도, `t_v`가 `R`과 같아도 성립하지 않는다.

### 7.4 수정안

```
기존   그 이하면 오탐 확인 부담이 절감을 먹는다
수정   그 이하면 고정 운영비가 절감을 먹는다
```

브리핑 0절에 따라 보고한다. 설계를 뒤집는 것이 아니라
**수식을 실제로 풀어보니 브리핑의 예상이 빗나간 것**이다.
브리핑 13절대로 그대로 적는다.

### 7.5 수식 밖의 고려

```
오탐이 많으면 → 담당자가 AI를 불신 → 결국 안 씀
```

**비용이 아니라 채택 여부의 문제**라 수식에 잡히지 않는다.
README에 한 줄 단서로 단다.

## 8. 모델 비교

| | Granite | PaddleOCR |
|---|---|---|
| 탐지율 r | 100.0% | 100.0% |
| 오탐률 p | 2.5% | 2.5% |
| **손익분기 N** | **동일** | **동일** |
| 모델 크기 | 515MB | 1.92GB |
| 장당 소요 (T4) | 26.3초 | 18.0초 |

**r, p가 동일하므로 손익분기도 동일하다.**
차이는 비용 수식이 아니라 배포 부담에서 나온다.

## 9. 결론 — 무엇이 결정하는가

| 변수 | 영향 |
|---|---|
| **C / R 비율** | **결정적** |
| R | 4배 → 손익분기 1/4 |
| 탐지율 r | 20%p 하락 시 4건 차이 |
| 오탐률 p | **거의 무영향** |

> 도입 여부는 모델 성능이 아니라
> **운영비가 재제출 비용의 몇 배인가**가 결정한다.

두 모델이 4·5단계에서 동률로 나온 것과 맞물린다.
**이 문제에서 모델 선택의 여지가 애초에 작다.**

은행 내부 무역서류 AI는 2020년부터 진행 중이었다.

### 10.2 손익분기 전제와의 충돌

```
AS-IS  사람이 점검
TO-BE  AI 도입
```

이 비교는 **AI를 아예 안 쓰는 곳**을 전제한다.
이미 쓰는 곳이라면 비교 대상이 "기반 모델 교체"가 된다.

### 10.3 다만 계산 틀은 유효하다

"AI 도입이 언제부터 이득인가"는 여전히 유효한 질문이고,
수식과 결론(C/R 비율이 결정적)도 그대로다.

**전제를 README에 정확히 적으면 된다.**

```markdown
## 전제
- 고객: 신용장 업무를 취급하는 은행
- 배포: 은행 내부 서버 (외부 API 호출 아님)
- IBM이 제공하는 것: 파싱 기반 모델 (완성 시스템 아님)
- 비교: 사람 점검(AS-IS) vs AI 도입(TO-BE)
- 범위 밖: 이미 도입한 곳의 솔루션 교체
```

### 10.4 경쟁사 이름은 README에 쓰지 않는다

브리핑 10절이 명시한다.

> README에 쓰지 말 것 — 로민 등 경쟁사 평가. 직접 검증하지 않은 내용

시장 조사 결과는 **면접 답변 재료**로만 둔다.

### 10.5 검증 실패 — "외국환은행 20개 안팎"

브리핑 4절의 이 수치는 확인하지 못했다.
"외국환업무취급기관"에 은행·증권·보험이 모두 포함되고,
검색 결과는 해외외국환업무취급기관(RFI)과 거래은행 지정 절차뿐이었다.

**README에서 이 숫자를 뺀다.** 법적 근거만 적는다.

> 외국환거래법상 신용장 업무는 은행만 취급할 수 있으며,
> 증권사는 기타외국환업무취급기관이라 지급·추심 업무를 취급하지 못한다.

## 13. README 반영 문구

> 두 모델의 탐지율과 오탐률이 동일하므로 손익분기도 동일하다.
> 이 계산의 목적은 모델 선택이 아니라 **AI 도입이 언제부터 이득인가**를 정하는 것이다.
>
> 재제출 1회 비용과 월 운영비의 절대 금액은 공개 자료가 없어 알 수 없다.
> 모든 금액을 재제출 1회 비용(R) 단위로 정규화해, **운영비가 재제출 몇 건에
> 해당하는가**라는 비율 하나로 답이 나오도록 했다. 모르는 값을 둘에서 하나로
> 줄인 것이지 없앤 것은 아니다.
>
> 월 고정비가 재제출 10건 값이고 수정·확인 비용이 재제출의 5% 수준이면
> 월 15건부터 이득이다. 재제출 비용이 클수록 손익분기가 낮아져, 5영업일 대기가
> 자금 회전에 치명적인 중소 수출기업이 가장 빨리 본전을 뽑는다.
>
> 브리핑 단계에서는 "오탐 확인 부담이 절감을 먹는다"고 보았으나,
> 실측 결과 오탐률을 2.5%에서 50%로 20배 올려도 손익분기가 변하지 않았다.
> 오탐 확인 비용이 재제출 비용에 비해 자릿수가 작기 때문이다.
> 절감을 먹는 것은 오탐이 아니라 **고정 운영비**다.
>
> 탐지율도 20%p 떨어져야 손익분기가 4건 움직인다.
> 도입 여부는 모델 성능이 아니라 운영비와 재제출 비용의 비율이 결정한다.
>
> 다만 오탐이 많으면 담당자가 시스템을 불신해 결국 쓰지 않게 될 수 있다.
> 이는 비용이 아니라 채택의 문제이며 수식에 잡히지 않는다.
